# Agent Note: 启动页签列表与单网址配置兼容

Status: implemented

## Problem

环境只能保存一个起始网址，无法同时启动多个页签，也无法暂停部分网址而保留配置。新增列表需要避免空列表或全部暂停时重新打开旧字段中的网址。

## Decision

`Profile.startupTabs` 是唯一配置来源，保存稳定 ID、网址、启用状态，数组顺序决定打开顺序。界面使用 `StartupTabDraft` 保留未通过校验的输入，保存时统一校验所有行，包括暂停项。

旧配置缺少新字段时，将 `startURL` 迁移为一个启用项，以环境 ID 作为稳定页签 ID，避免重复读取旧记录被误判为外部修改。新字段存在时，即使为空也不回退。编码时附带第一个启用网址作为旧字段投影；全部暂停时不输出旧字段。旧单网址代码入口的赋值表示替换整个列表。

`SafarierWorkspace.runnerSpec` 统一筛选启用项，显式网址覆盖本次启动，探针仅取第一项。Runner 通过重复 `--url` 有序传递网址。`BrowserSession.start(urls:)` 创建一个窗口，再复用原生 `openTab`，最后选中第一项。空列表打开一个起始页。

命令行创建和更新环境支持重复 `--url`，传入时替换整个列表，省略则保留，`none` 清空。其他选项继续保持最后一个值生效。环境运行期间修改只影响下次启动。手动恢复会话仍独立于自动启动列表。

## Alternatives considered

- 保留独立的单网址和多网址两套配置：旧调用方改动少，但空列表及暂停语义容易被旧字段覆盖，故仅保留单网址的兼容投影。
- 使用多行文本输入：编辑多个网址简单，但逐项暂停、稳定身份和排序操作不直观，因此采用带勾选及上下移动按钮的列表。
- 启动时自动恢复上次会话：可以复用历史网址，但可能再次打开已暂停项，也改变现有手动恢复语义，因此保持恢复功能独立。

## Consequences

列表保留暂停项，旧配置可无损读取，参数顺序与原生窗口页签顺序一致。代价是配置编码和单网址兼容入口需要同步维护；旧版无法保留完整列表，回退前需要备份 `profiles.json`。上下移动满足当前排序需求，拖拽和批量导入没有进入本次范围。

## Testing

先运行三项回归测试，原实现出现六处断言失败；实现后迁移、暂停、顺序、覆盖、复制、语言重启参数、表单保存与还原、命令行及真实 AppKit 页签测试通过。

`swift test` 暴露 `NodeLatencyBatchTests` 的既有失败；在 scratch 中通过 `git archive HEAD` 创建原始提交副本，并运行 `swift test --package-path <基线目录> --filter NodeLatencyBatchTests`，复现相同失败和缺少 `batch-state` 的错误。

最终执行 `swift test --skip NodeLatencyBatchTests`：618 项，15 项按环境条件跳过，零失败；编译无警告。`git diff --check` 通过。

未完成人工界面点击和视觉检查：当前环境没有 `orca`，测试进程的 SwiftUI 辅助功能子树为空，因此没有保留无法有效验证的实验性交互测试。真实浏览窗口的同窗多页签、顺序和首项选中已由 AppKit 测试覆盖。
